## [Unreleased]

### Исправлено
- **FIX-32: печать по-русски больше не роняет ни приложение, ни CI.**
  - **Что было.** Windows печатает в кодовую страницу системы. На русской
    установке это cp1251 и всё работает, а на англоязычной (cp1252) любая
    русская буква даёт `UnicodeEncodeError`. Воспроизведено принудительной
    кодировкой: `python cleaner.py 00000419 --plan` доходил до вывода отчёта
    и падал на нём — после того, как всё сделал. На runner'е GitHub с тем же
    эффектом падал шаг проверки покрытия: он печатал слово «общее».
  - **Почему раньше было незаметно.** У разработчика русская Windows, баг не
    воспроизводится; у пользователя с англоязычной Windows он воспроизводится
    всегда. Ровно тот класс дефекта, который FIX-31 уже объяснял для другого
    слоя: под Windows один и тот же код ведёт себя по-разному в зависимости
    от машины.
  - **Решение.** `applog.make_output_safe()` — одна реализация на три точки
    входа (CLI `cleaner.py`, `sign_exe.py`, `scripts/check_coverage.py`).
    Кодировку по умолчанию НЕ меняем: на cp1251 вывод остаётся читаемым, а на
    cp1252 русские буквы становятся «?» — печать не падает. Принудительно
    UTF-8 включается только там, где вывод уходит в конвейер или файл
    (журнал CI), иначе в логе вместо слов были бы вопросительные знаки.
    Раньше в `check_coverage.py` была своя копия этой логики — при равенстве
    строк она и разошлась бы с общей.
- **Мьютексные тесты больше не зависят от того, один ли идёт прогон.**
  Замерено, а не предположено: пять последовательных прогонов — зелено, два
  параллельных — красные, каждый на своём тесте. Причины оказались две, и
  обе — общие имена на два процесса:
  - имена мьютексов были фиксированными (`TestMutexPoll`,
    `Local\TestMutexRestart_…`) — именованный мьютекс принадлежит сессии,
    поэтому второй процесс видел «занято»;
  - подчиняющие скрипты писались в постоянные `klc_test_old.py`, и `finally`
    одного прогона удалял файл, пока второй процесс его запускал.
  Теперь имена дополняются PID (`conftest.unique_mutex_name`), а вместо
  «подождать 0,5 с, пока первый процесс создаст мьютекс» тест ждёт самого
  состояния: под нагрузкой второй процесс раньше успевал перехватить мьютекс,
  и «старый» выходил с кодом 1. Проверено тремя парами параллельных прогонов
  подряд — все зелёные.

### Удалено
- **Операция `Copy-UserInternationalSettingsToSystem` удалена из проекта
  (решение владельца, 26.09.2026).** С v1.1.0 она существовала как отдельная
  необратимая команда `--sync-welcome`: применить текущий список языков к
  Экрану приветствия и профилю новых пользователей. Проверка на живых
  машинах показала, что чинить ей нечего, а сообщала она о своей недоступности
  двумя способами неправильно.
  - **Чинить нечего.** На обеих проверенных машинах (Win11 build 26200 и Win10
    build 19045) в `HKU\.DEFAULT\Keyboard Layout\Preload` лежит ровно тот же
    набор раскладок, что и у текущего пользователя — `00000419` и `00000409`.
    Лишней раскладки в профиле по умолчанию нет ни на одной из них.
  - **На Windows 10 команда невозможна в принципе.** `Get-Command
    Copy-UserInternationalSettingsToSystem` возвращает `False`, прямой вызов —
    `CommandNotFoundException`. Приложение при этом печатало предупреждение о
    необратимых изменениях, а затем `sync_welcome: FAILED`: то есть ложное
    предупреждение о необратимом действии там, где ничего не произошло и
    произойти не могло, и отказ без единого слова о причине.
  - **Побочная находка, которую удаление снимает лишь в этом месте: CLI не
    журналирует.** `setup_logging()` вызывается только из GUI-входа
    (`main.py`), а модули при импорте добавляют `NullHandler` (`cleaner.py`,
    `scanner.py`, `config.py`, `i18n.py`, `ui_theme.py`). Сообщение
    `logger.warning("Copy-UserInternationalSettingsToSystem: returncode=…")`
    уходило в никуда, а файла журнала при запуске из командной строки не
    создавалось вовсе — причина отказа не была видна нигде. Общий дефект
    молчания CLI остаётся и требует отдельного решения.
  - **Удалено:** функция `sync_welcome_screen_settings()`, флаг
    `--sync-welcome`, PowerShell-скрипт `layout_cleaner_sync_welcome.ps1`,
    право `Capability.WELCOME_SYNC`, ключ таймаута `powershell_welcome_sync`,
    упоминания в README и ARCHITECTURE. Прежний тест `TestWelcomeSyncDecoupled`
    (spy «функция не вызывается») заменён на `TestWelcomeSyncRemoved`, который
    фиксирует само отсутствие: функции, права, скрипта, флага и ключа таймаута.
  - **Проверено:** `549 passed` (`-m "not live"`), `ruff` и `mypy` чисты.

## [1.1.0] — 2026-09-26

В этой версии четыре P0-исправления безопасности и диагностики, найденные на
живой машине. Две из них меняют поведение, заметное пользователю: повышение прав
больше не теряет `--sandbox`, а приложение теперь честно сообщает, когда
переключатель раскладок расходится с настройками сессии.

### Исправлено
- **FIX-31 (P0, найдено на живой машине ручным экспериментом): приложение больше не рапортует «успех» при переключателе, который продолжает показывать удалённую раскладку.** Замеренная на живой машине картина: после удаления английской раскладки `Preload` содержал только `00000419`, `Get-WinUserLanguageList` возвращал только `ru`, `CTF\Assemblies` тоже был подчищен — а свежий процесс PowerShell продолжал возвращать `0419` **и** `0409` из `GetKeyboardLayoutList()`. То есть раскладка оставалась доступна пользователю в панели переключения, и требовался выход из системы.
  - **Почему старая проверка это пропустила.** `check_switcher_consistency()` сверяла `Preload`, список языков и кеш `CTF` — а это ровно те три хранилища, которые операция только что привела в порядок. Сверяя их между собой, она гарантированно находила согласие, даже когда переключатель реально сломан. Реестр хранит **намерение**, панель — **состояние сессии**, и расходятся они в обе стороны.
  - **Новый источник истины.** `winapi.get_keyboard_layout_list()` (прототип `GetKeyboardLayoutList` объявлен в `winapi.py` согласно FIX-19) читает то, что панель показывает фактически. HKL нормализуется в полный 8-HEX KLID отбрасыванием старшего слова — это тип клавиатуры, а не язык; без этого сравнение с реестром не сойдётся никогда.
  - **Два новых поля отчёта.** `switcher_missing` — раскладка объявлена в настройках, но панель её не показывает; `switcher_stale` — панель показывает раскладку, которой уже нет в настройках. Оба учитываются в `is_switcher_consistent()`. Если прочитать состояние не удалось, поля **не добавляются** вовсе: непрочитанное состояние нельзя превращать в ложный диагноз с советом выйти из системы.
  - **`ctf_missing` перестал быть диагнозом.** FIX-27 вывел это поле к пользователю как поломку, и это было ошибкой: на живой машине ветки `CTF\Assemblies\0x00000409` нет, а английская раскладка прекрасно переключается — простым латинским раскладкам такая ветка не нужна. Предупреждение с советом перезапустить службу ввода было ложной тревогой, отправлявшей пользователя делать бессмысленную перезагрузку. Поле остаётся в сообщении как справочная деталь и больше **не** требует действий. Прежний тест `test_ctf_missing_reaches_the_user`, требовавший именно этого поведения, переписан: он закреплял непроверенное допущение.
  - **Совет стал точным.** Оба случая расхождения с сессией лечатся только выходом и повторным входом: профиль ввода живёт в сеанстве входа, и ни `Set-WinUserLanguageList`, ни перезапуск `ctfmon` его не обновляют — проверено на живой машине, где перезапуск обеих служб не помог. Ключи `dlg_switcher_signout_advice`, `dlg_switcher_absent`, `dlg_switcher_session_stale`, `dlg_switcher_ctf_note` добавлены во все 6 локалей; осиротевшие `dlg_switcher_ctf_missing` / `dlg_switcher_ctf_advice` удалены.
  - **Проверено:** `572 passed`, `ruff` и `mypy` чисты. Детект подтверждён на живом реестре с подменой только чтения сессии (в обе стороны: и `switcher_stale`, и `switcher_missing`).
- **FIX-30 (P0, найдено на живой машине при ручном тестировании exe): повышение прав больше не теряет `--sandbox`.** Пользователь запускал приложение с `--sandbox` именно затем, чтобы не трогать систему, а в журнале появилось `params= --elevate --parent-sid S-1-5-21-...` **без** `--sandbox`, и удаление раскладки ушло по-настоящему. Причина: `_restart_as_admin` читал глобальную `main.SANDBOX_MODE` — это снимок, снятый при импорте модуля **до** разбора командной строки, поэтому флаг в неё не попадал (он активирует песочницу через `activate_sandbox()`, но не в это поле). Теперь читается живое состояние `config.is_sandbox_enabled()`, которым управляют и флаг командной строки, и галочка в GUI. Регрессионный тест проверен в обе стороны: со старой строкой падает с «песочница потеряна при повышении прав», с исправлением проходит; второй тест фиксирует обратное направление, чтобы флаг не начали добавлять безусловно. Это ровно тот класс дефекта, из-за которого песочница переставала быть гарантией именно там, где её и просили.
- **FIX-29 (P0, разрушительные пути защищены моделью прав, а не памятью разработчика): live-тесты больше не могут вызвать разрушительную операцию по живой системе — в принципе, а не «если не забыли подмену».** FIX-28 сделал утечки громкими (барьеры в `conftest.py`, падающие функции). Но барьер стоял **в тестах**, и защита держалась на том, что каждый новый тест сам вспомнит про подмену. Дважды не вспомнили — у пользователя пропала русская раскладка. Теперь проверка стоит **внутри самих разрушительных функций**, и забыть её нельзя: не защищённой останется функция, а не тест.
  - Новый модуль `capabilities.py`: deny-by-default, шесть видов доступа — `REGISTRY_MUTATE`, `REG_IMPORT`, `LANGUAGE_LIST`, `INPUT_SERVICES`, `CLOUD_SYNC_POLICY`, `WELCOME_SYNC`. Права разведены, потому что опасность разная: `LANGUAGE_LIST` перезаписывает список языков целиком и песочницей не покрывается (WinRT минует реестр), а `WELCOME_SYNC` необратим в принципе (FIX-4) и в обычный набор прав не входит — выдаётся только по явному `--sync-welcome`.
  - `require()` стоит в: `mutate._delete_registry_value`, `_delete_subtree`, `_clean_{preload,substitutes,branch_recursive,intl_profile,ctf_profiles}` (только при `delete=True` — dry-run остаётся безопасным и работает без права), `backup.restore_registry_backup`, `langlist._run_cleanup_script(apply=True)`, `_sync_language_list_via_powershell`, `restore_language_list`, `cleaner._stop_ctfmon`/`_start_ctfmon`, `settings.disable/enable_language_sync`, `sync_welcome_screen_settings`.
  - Права выдаются **только** в двух точках входа: `main.main()` и CLI `cleaner.py`. Ни импорт модуля, ни вызов из GUI-функции прав не даёт.
  - `conftest.py`: autouse-фикстура снимает все права перед каждым тестом (состояние процесса общее, иначе право утекло бы в следующий тест) плюс фикстура `granted` для явного opt-in. Старые барьеры FIX-28 удалены — они покрывались и путали двумя разными ошибками на одну проблему.
  - **Побочная находка:** `capabilities` не был в `hiddenimports` спеки, и упал бы не в CI, а у пользователя на exe. Добавлен `TestPackagingCoversEveryModule` — транзитивное замыкание импортов от `main.py` плюс явный список `hiddenimports`; новый модуль без обоих путей валит сборку.
  - **Проверено на живой машине:** проба всех шести разрушительных путей без прав — все заблокированы, `LangList` и `Preload` не изменились; `563 passed`, `ruff` и `mypy` чисты; состояние клавиатуры до и после полного прогона идентично.
- **FIX-28 (P0, тестовый прогон стирал русскую раскладку у пользователя): тесты больше не могут убить службу ввода и не могут вызвать `Set-WinUserLanguageList` по живой системе.** Это и был искомый «актор»: не облачная синхронизация и не Windows, а **собственный тестовый набор проекта**, запускавший настоящие PowerShell-скрипты по реальному профилю пользователя. - **FIX-28 (P0, тестовый прогон стирал русскую раскладку у пользователя): тесты больше не могут убить службу ввода и не могут вызвать `Set-WinUserLanguageList` по живой системе.** Это и был искомый «актор»: не облачная синхронизация и не Windows, а **собственный тестовый набор проекта**, запускавший настоящие PowerShell-скрипты по реальному профилю пользователя. Найдено два независимых механизма, оба подтверждены командной строкой из лога.
  - **Механизм 1 — `layout_cleaner_cleanup.ps1 -Apply` с настоящим KLID.** `test_manifest_drift.py::TestDeleteLayoutManifestIntegration` и три «живых» теста в `test_sandbox.py` вызывали `delete_layout`, а тот — `langlist._run_cleanup_script(..., apply=True)`. Скрипт внутри вызывает `Set-WinUserLanguageList -Force`, который **заменяет список языков целиком**. В E2E-тесте KLID был `00000419` — то есть тест удалял настоящую русскую раскладку. Почему подмена не спасала: тест глушил `langlist._sync_language_list_via_powershell`, но `cleaner` импортирует её **именем** (`from langlist import ...`), так что подмена не действовала на путь `delete_layout`; а `_sync_language_list_via_powershell` внутри зовёт `_run_cleanup_script` по локальной ссылке модуля — мимо реэкспорта в `cleaner`. Подменены обе ссылки.
  - **Механизм 2 — живой `ctfmon`.** `CtfmonSuspender` останавливал `ctfmon.exe`/`TextInputHost.exe` настоящим `Stop-Process -Force` **даже в режиме песочницы**: песочница изолирует реестр и блокирует WinRT-API, но управление процессами мимо неё проходило. `ctfmon` владеет кешем TSF в ОЗУ; после его убийства Windows пересобирает кеш из реестра, и при расхождении `Preload` / `User Profile` / `CTF\Assemblies` пересборка молча теряет раскладку — при том, что в Параметрах языка она остаётся «установленной». `CtfmonSuspender` теперь в песочнице — полный no-op (и `__exit__` возвращается до `_start_ctfmon`, иначе «восстановление» само перезапускало бы службу у живого пользователя).
  - **Системный барьер вместо памяти разработчика.** Раньше каждая подмена была делом отдельного теста, и одна забытая строка стоила реальной поломки — дважды. В `conftest.py` добавлены autouse-фикстуры `_forbid_live_input_services` и `_forbid_live_language_list`, которые подменяют управление ctfmon и запуск скриптов списка языков на функции, **падающие с `LiveInputServiceLeakError` / `LiveLanguageListLeakError`**. Барьер не молчит: утечка обязана быть видна немедленно и адресно, а не через сломанную раскладку у человека. Барьер сразу выявил все пять утечек. Маркер `input_services_suspended.marker` (FIX-13) отправлен во временный каталог.
  - **Проверено на живой машине:** `554 passed`, `ruff check` и `mypy` чисты, за полный прогон — **ноль** остановок `ctfmon` и ноль вызовов `Set-WinUserLanguageList`; список языков, `Preload` и `User Profile` после прогона не изменились.
- **FIX-25 (P1, потеря языка пользователя): снимок списка языков больше не может заменить его одним несуществующим языком.** Корневая причина — `layout_cleaner_backup.ps1` делал `$langs = @(Get-WinUserLanguageList)`, а `Get-WinUserLanguageList` возвращает список как **один объект**. `@()` его не разворачивал, поэтому снимок на N языков создавался одной записью вида `{"LanguageTag":["ru","en-US"],"InputMethodTips":[<все>]}`. Дальше дефект множился по трём слоям: Python «чинил» массив, молча брав первый тег; `restore.ps1` склеивал массив в строку `"ru en-US"`; `New-WinUserLanguageList` создавал ОДИН язык с несуществующим тегом, и `Set-WinUserLanguageList -Force` **заменял весь список языков** — печатая `SUCCESS`. Клиентский симптом: язык пропадал из панели переключателя, оставаясь «установленным» в Параметрах языка; помогала только перезагрузка. Исправлено: коллекция разворачивается явно (как в FIX-24 для cleanup); `restore.ps1` стал fail-closed — нескалярный тег и тег вне BCP-47 отклоняются с `INVALID_TAG` **до** любого вызова WinRT, частичного применения нет; Python отклоняет такие снимки до запуска PowerShell. Заодно вскрыт и удалён «помогающий» код в `langlist._parse_langlist_entry`, который маскировал потерю языка.
- **Песочница изолирует список языков.** `Set-WinUserLanguageList` — WinRT-API, минующий реестр, поэтому изоляция веток под `_SANDBOX_ROOT` его не покрывала: sandbox/live-тесты и CLI `--sandbox` могли переустановить **реальный** список языков пользователя. Добавлен флаг `-Sandbox` в `layout_cleaner_restore.ps1`, `layout_cleaner_cleanup.ps1`, `layout_cleaner_sync.ps1` (ответ `SANDBOX_SKIPPED`), который `langlist.py` передаёт при активной песочнице.
- **`dlg_no_backups` форматируется.** `main.py` передаёт `path=`, а `en/ru/es` содержали `{dir}`: `i18n.fmt` ловил `KeyError` и возвращал строку без подстановки — пользователь видел `{dir}` вместо пути к папке бэкапов. Локали приведены к `{path}`.

### Примечание
- Строка в stdout любого `.ps1` должна быть **ASCII**: файлы хранятся без UTF-8 BOM, Windows PowerShell 5.1 читает их в ANSI (CP1251), и UTF-8-байты `—` (E2 80 94) превращаются в `”`, которую PowerShell считает разделителем строки — литерал роняет разбор всего скрипта. Кириллица допустима только в комментариях. Причина зафиксирована в шапке `layout_cleaner_restore.ps1`.
