# Keyboard Layout Cleaner

GUI-утилита для поиска и безопасного удаления «фантомных» раскладок
клавиатуры в Windows (Python 3.10+, CustomTkinter, только Windows).

> 💡 **Скачали программу, а SmartScreen или антивирус предупредил?**
> Пугаться не нужно — это частая ситуация для открытых программ без платной
> подписи. Что делать, за пару минут:
> [«Антивирус / SmartScreen»](#антивирус--smartscreen).

## Возможности

- Сканер реестра: `HKCU\Keyboard Layout\Preload/Substitutes`,
  `HKCU\Control Panel\International\User Profile`,
  `HKCU\Software\Microsoft\CTF`, `HKEY_USERS\.DEFAULT\Keyboard Layout\Preload`,
  каталог имён `HKLM\...\Keyboard Layouts`, а также список языков через
  PowerShell (`Get-WinUserLanguageList`).
- Сопоставление BCP-47 ⇄ KLID HEX, динамические имена раскладок из HKLM.
- **Dry-run**: перед удалением показывается план — какие значения в каких
  ветках и какие раскладки/языки будут затронуты.
- Порядок «бэкап → удаление → синхронизация»: перед изменениями создаётся
  один `.reg` со всеми ветками (UTF-16 LE, BOM) **и** JSON-копия текущего
  списка языков.
- Рекурсивная очистка `User Profile` и `CTF` (включая подключи).
- Синхронизация списка языков выполняется «на месте»
  (`InputMethodTips.Remove`) — прочие настройки языка сохраняются;
  языки без раскладок удаляются целиком; список языков никогда не
  опустошается полностью.
- Журналирование в `layout_cleaner.log`.
- **Два интерфейса** (кнопка в шапке): «⌨ Терминал» — чёрный фон,
  моноширинный шрифт, плоские рамки, зелёные/циановые акценты; и
  «▦ Обычный» — классическая тема CustomTkinter. Выбор запоминается.
- **Яркость шрифтов** (меню в шапке): Тусклая / Обычная / Яркая /
  Максимальная — масштабирует все текстовые цвета без изменения фона;
  выбор тоже сохраняется (`%LOCALAPPDATA%\KeyboardLayoutCleaner\ui_prefs.json`).

## Установка и запуск

```bat
python -m pip install -r requirements.txt
python main.py
```

## Использование

1. «Сканировать систему» — поиск раскладок. Найденное сразу показывается
   списком в панели деталей; подсказка и пульсирующая подсветка указывают
   следующий шаг.
2. **Одна строка — одна раскладка.** Сколько бы записей Windows ни оставила
   в разных ветках (`Preload`, `User Profile`, `CTF`, список языков), в списке
   она одна: с именем из каталога Windows, кодом и количеством записей.
   Все коды, которыми Windows записала эту раскладку (в том числе HKL
   вида `68748313`), видны в подробностях — в строке «В реестре».
3. У каждой строки есть **метка состояния**:
   - `в списке языков` — раскладка установлена и используется;
   - `похоже на кеш активной раскладки` — записи только в CTF, но язык
     активен в Windows: это кеш, который Windows пересоздаст;
   - `только в кеше CTF — вероятный остаток` — язык в списке отсутствует,
     записи остались лишь в кеше: вероятный фантом;
   - `в настройках, но не переключается` — прописана в реестре, однако
     `GetKeyboardLayoutList` её не показывает.
4. Выберите раскладку в списке — внизу появятся **все** сканируемые
   разделы со статусом «обнаружено / не обнаружено» и значениями записей.
5. «Удалить раскладку» — приложение покажет **план удаления** (dry-run)
   и спросит подтверждение.
6. После удаления данные автоматически пересканируются.
7. «↩ Восстановить из бэкапа» — применяет значения бэкапа поверх текущего реестра (merge): удалённое возвращается, появившееся позже — остаётся. Выберите бэкап
   из списка (дата + состав), проверьте предпросмотр разделов и
   подтвердите. Будут применены `.reg` и, если есть снимок, список языков
   (`.langlist.json`). Если в бэкапе есть `HKU\.DEFAULT`, а прав нет —
   Windows запросит UAC прямо на импорт. Если раскладка не появилась
   сразу — выйдите из системы и войдите снова.

> Кнопка «🔑 Перезапустить как Администратор» видна только если прав нет:
> без админа системная ветка `HKU\.DEFAULT` пропускается — в деталях такая
> запись помечена «БЕЗ АДМИНА БУДЕТ ПРОПУЩЕНО», а Windows может вернуть
> раскладку после перезагрузки.

## Безопасность

- Все ветки экспортируются в `.reg` **до** удаления; список языков — в
  `.langlist.json`. Бэкапы лежат в `backups\` рядом с программой и
  применяются обратно кнопкой «↩ Восстановить из бэкапа».
- Запись в `HKEY_USERS\.DEFAULT` выполняется только с правами
  администратора; без прав ветка пропускается (баннер + кнопка
  «Перезапустить как Администратор», UAC).
- **Кеш TSF (CTF)**: фантомные профили удаляются целиком из
  `HKCU\Software\Microsoft\CTF\Assemblies` и `...\SortOrder\AssemblyItem`
  (включая десятичные HKL-значения вида `68748313` = `0x04190419`),
  а процессы ввода (`ctfmon.exe`, `TextInputHost.exe`) **останавливаются
  ДО** начала очистки и запускаются заново ПОСЛЕ всех операций с
  реестром и PowerShell — иначе служба держит кеш в памяти и переносит
  фантом обратно в реестр (гонка состояний). Если перезапуск не удался —
  достаточно перезагрузить ПК.
- **User Profile** очищается ТОЧЕЧНО: в профиле языка
  (`...\User Profile\en-GB`) удаляются только записи конкретной раскладки
  (`KeyboardLayoutPreload`, `InputMethodOverride`), **не** весь профиль
  языка и **не** активный язык из `Languages` — возможность вернуть
  раскладку через «Параметры → Язык и регион» сохраняется.
- **Экран приветствия не изменяется**: удаление раскладки не выполняет
  `Copy-UserInternationalSettingsToSystem`. Эта команда перезаписывает
  `HKEY_USERS\.DEFAULT` и профиль новых пользователей (весь набор
  международных настроек, не только раскладки), а эти ветки в бэкап не
  входят — восстановить было бы невозможно. Отдельной команды для неё
  больше нет: операция удалена как необратимая и не нужная (проверено на
  живой машине — в профиле по умолчанию лежит тот же набор раскладок,
  что и у текущего пользователя). Если фантомная раскладка всё же видна
  на Экране приветствия, её придётся убрать средствами Windows вручную.
- Автотесты записи/удаления выполняются **только** в sandbox-ключе
  `HKCU\Software\KeyboardCleanerTest` (см. `test_sandbox.py`).
  Реальное удаление раскладок из живого профиля тестируйте в VM
  (Windows Sandbox / Hyper-V).

## Восстановление

1. Реестр: `reg import keyboard_layout_backup_<timestamp>.reg`.
2. Список языков (Python, вызывает PowerShell под капотом):

```python
from cleaner import restore_language_list
restore_language_list("keyboard_layout_backup_<timestamp>.langlist.json")
```

Снимок `.langlist.json` содержит полный изменяемый набор языка (FIX-3):
`LanguageTag`, раскладки (`InputMethodTips`) и настройки письма
(`Handwriting`, `Spellchecking`) — без них восстановление возвращало бы язык с
настройками по умолчанию. Старые снимки (только язык + раскладки)
восстанавливаются тоже, но настройки письма примут значения по умолчанию.
Файл с TIP неверного формата (ожидается `0409:00000409` или
`0409:{...GUID...}`) не применяется целиком — частичное восстановление
не выполняется.

### Sidecar-манифест (FIX-6)

Рядом с каждым `.reg` создаётся `<имя>.manifest.json` — **аудит, а не условие
отката**. Он содержит версию приложения, KLID, список веток с разбивкой
`exported` / `failed` / `skipped` и снимок значений, найденных **до** удаления
(путь, имя, тип, значение).

- **Восстановление работает и без манифеста.** `reg import` — самостоятельный
  путь отката; манифест можно не переносить, и откат не сломается.
- Манифест нужен, чтобы разобрать инцидент: что планировалось удалить, какие
  ветки не удалось выгрузить, что осталось в реестре. Если после операции
  появилось расхождение «найдено ≠ удалено», приложение показывает его в
  диалоге результата как «Дрейф плана» и пишет в лог.

## Портативный режим (флешка)

- Журнал (`layout_cleaner.log`) и бэкапы (`backups\`) создаются **рядом
  с exe** — приложение ничего не пишет во временные папки и не требует
  установки (спека: `keyboard_cleaner.spec`, тип сборки onedir — старт
  с USB быстрее, чем у onefile, т.к. нет распаковки при каждом запуске).
- Права администратора: UAC при старте не запрашивается (asInvoker);
  для очистки ветки `HKU\.DEFAULT` нажмите
  «🔑 Перезапустить как Администратор» внутри приложения.
- При elevation UAC может попросить учётные данные другого администратора — тогда приложение работает в его профиле и изменяет его `HKCU`. Чтобы этого не случилось, передайте учётные данные того же пользователя, от имени которого запущено приложение.
- При первом запуске возможно предупреждение SmartScreen; порядок действий
  описан в разделе «Антивирус / SmartScreen» ниже.
- Пересборка после правок кода: `build_exe.bat`.

## Антивирус / SmartScreen

> **Пугаться не нужно.** Если SmartScreen или антивирус «ругнулся» на
> программу — это неприятно, но в большинстве таких случаев дело не в вирусе,
> а в том, как программа собрана. Заблокированный файл не запускается и ничего
> не меняет на компьютере — ваш компьютер в безопасности. Ниже — что делать:
> сначала проверка файла своими руками, затем три простых шага и подробности.

### Проверьте файл сами — 2 минуты, и вопрос закрыт

Программа **ничего не прячет**: весь её код, скрипты сборки и тесты лежат в
этом репозитории, а EXE можно не только проверить, но и пересобрать самому по
[BUILD.md](BUILD.md). Ниже — что именно проверять.

Опубликованный релиз — хеши считаются автоматически при публикации релиза,
руками ничего править не нужно:

> Хеши относятся **только** к указанному релизу. В ветке `main` могут быть
> изменения, ещё не выпущенные, поэтому файл, собранный заново, будет иметь
> другой хеш — это нормально и ничего не говорит о подмене.

Сверить хеш одной командой в PowerShell:

```powershell
(Get-FileHash .\KeyboardLayoutCleaner-1.1.0-portable.zip -Algorithm SHA256).Hash
```

> Если на GitHub лежит файл `SHA256SUMS.txt` (он кладётся рядом с архивом),
> сверять можно одной командой `certutil -hashfile файл SHA256` для ZIP и
> любой утилитой `sha256sum -c` для `SHA256SUMS.txt`.

**Онлайн-проверка** — файл загружается на сторонний сервис, это осознанный
выбор и ничего личного в нём нет:

- [VirusTotal](https://www.virustotal.com/gui/home) — проверяют сразу несколько
  десятков антивирусов, это самый наглядный результат;
- [Dr.Web — «Проверить файл»](https://vms.drweb.ru/scan_file/) — бесплатно и без
  регистрации. **Лимит 10 МБ**, а портативный архив больше: загружайте
  `KeyboardLayoutCleaner.exe` из распакованного архива (около 3 МБ), его хеш —
  во второй строке таблицы выше.

**Бесплатные «лечащие» сканеры** — запускаются с флешки, установка не нужны.
Пригодятся, если хотите проверить компьютер целиком, а не один файл:

- [Kaspersky Virus Removal Tool](https://www.kaspersky.ru/downloads/free-virus-removal-tool) —
  умеет и перепроверять срабатывания;
- [Dr.Web CureIt!](https://free.drweb.ru/cureit/) — то же от Dr.Web.

Если у нескольких независимых сканеров файл чист, а исходный код открыт и
собирается по инструкции, срабатывание с высокой вероятностью ложное.
Окончательный вердикт по конкретному образцу всё равно выносит производитель
антивируса — см. «Если обнаружена угроза» ниже.

### Коротко: три простых шага

1. **Ничего не отключайте и не восстанавливайте.** Файл в карантине — значит,
   программа просто не запустится; это нормально. Не добавляйте исключения,
   не выключайте защиту и не восстанавливайте файл — необходимости в этом нет.
2. **Обновите антивирус и повторите проверку.** «Безопасность Windows →
   Защита от вирусов и угроз → Обновления защиты → Проверка обновлений»,
   затем повторно проверьте скачанный файл или папку.
3. **Сделайте скриншот сообщения и напишите в
   [Issues](https://github.com/mrzsrg/KeyboardLayoutCleaner/issues)**:
   укажите название угрозы (например, `Trojan:Win32/Sabsik.FL.A!ml`) и то,
   откуда скачивали файл. По желанию отправьте файл в
   [Microsoft на анализ](https://www.microsoft.com/en-us/wdsi/filesubmission) —
   так срабатывание снимут быстрее для всех пользователей. Подробная
   инструкция — ниже.

### Почему антивирус может «ругаться»

- **Исходный код полностью открыт.** Код, скрипты сборки, тесты и все
  остальные файлы приложения лежат в открытом доступе в этом репозитории —
  любой желающий может их посмотреть, а собрать программу самому можно по
  инструкции [BUILD.md](BUILD.md).
- **Способ сборки «выглядит» подозрительным для эвристики.** Программа
  написана на Python и упакована PyInstaller'ом, EXE без платной цифровой
  подписи, внутри запускается PowerShell и правятся ветки реестра. Такие же
  признаки есть у многих небольших open-source программ, поэтому антивирусы
  помечают их эвристикой — в названии детекта это суффикс `!ml`
  (машинная эвристика, а не точная сигнатура известного вируса).
- Это **частая картина для open-source программ, но не доказательство ни
  заражения, ни безопасности**: окончательный вердикт даёт только анализ
  образца производителем антивируса, поэтому ниже — конкретные шаги,
  включая отправку файла на проверку.

### Возможные проблемы и действия

| Что произошло | Что делать |
| --- | --- |
| SmartScreen сообщает «Система Windows защитила ваш компьютер» / «Неизвестный издатель», но антивирус не сообщает об угрозе | Это может быть предупреждение о репутации файла или издателя, а не обнаружение вируса. Проверьте источник загрузки, версию и сведения о подписи. При сомнениях отмените запуск и обратитесь к разработчику; не обходите предупреждение автоматически. |
| Антивирус сообщает название угрозы (например, `Trojan:Win32/Sabsik.FL.A!ml`), блокирует ZIP/EXE или помещает его в карантин | Не запускайте файл, оставьте его в карантине и выполните действия ниже. Название угрозы само по себе не доказывает ни заражение, ни ложное срабатывание. |
| После распаковки исчез EXE или DLL, приложение не запускается | Проверьте журнал антивируса. Если он удалил компонент, не восстанавливайте его и не скачивайте отдельные DLL со сторонних сайтов. Если блокировок нет, проверьте, что распакована вся папка релиза, а не только EXE. |
| Защита сообщает «Сбой карантина» или обнаружение повторяется | Обновите базы и выполните полную проверку. Если проблема сохраняется, используйте автономную проверку Microsoft Defender (сохраните работу: потребуется перезагрузка) либо обратитесь в поддержку своего антивируса. |
| Запуск запрещён политикой организации | Обратитесь к системному администратору. Не меняйте корпоративные политики и исключения самостоятельно. |

### Если обнаружена угроза

1. **Не отключайте защиту, не добавляйте исключения и не восстанавливайте
   заблокированный файл ради запуска.** Не используйте запуск от администратора,
   пересборку или запуск из исходников как способ обойти блокировку.
2. Откройте «Безопасность Windows → Защита от вирусов и угроз → Журнал защиты»
   (для другого антивируса — его журнал/карантин). Запишите название угрозы,
   время, затронутый файл и результат действия антивируса.
3. Обновите базы антивируса. Если приложение уже запускалось или есть другие
   обнаружения, выполните полную проверку компьютера. На рабочем компьютере
   уведомите администратора.
4. Проверьте источник: загружать релизы следует со
   [страницы релизов проекта](https://github.com/mrzsrg/KeyboardLayoutCleaner/releases).
   Если автор опубликовал SHA256, сравнивайте хэш **того же ZIP или EXE**.
   Совпадение подтверждает соответствие опубликованному файлу, но не безопасность.
   Если файл удалён или в карантине, не извлекайте его ради вычисления хэша.
5. Создайте сообщение в
   [Issues](https://github.com/mrzsrg/KeyboardLayoutCleaner/issues), указав:
   - версию приложения, имя архива и ссылку на релиз;
   - версию Windows, название антивируса и версию его баз;
   - точное название угрозы и этап блокировки: скачивание, распаковка или запуск;
   - SHA256, если доступен, и снимок сообщения без персональных данных;
   - запускали ли вы приложение до обнаружения.
   Не прикладывайте публично бэкапы реестра, личные данные или подозрительный EXE.
6. Для Defender используйте
   [официальную форму анализа Microsoft](https://www.microsoft.com/en-us/wdsi/filesubmission).
   Выберите свою роль (пользователь или разработчик), приложите сведения о детекте
   и ссылку на релиз. Если образец недоступен из-за карантина, передайте сведения
   разработчику для отправки исходного артефакта — обходить защиту не нужно.
   Для другого антивируса обратитесь в официальную поддержку его производителя.
7. Дождитесь результата анализа и рекомендаций производителя антивируса /
   разработчика для конкретной версии. Исчезновение детекта после обновления
   баз или пересборки само по себе не доказывает безопасность.

### Метаданные и цифровая подпись

- `FileVersion` — сведения о версии, а не цифровая подпись.
- Authenticode подтверждает издателя при доверенной цепочке сертификатов и
  целостность подписанного содержимого; не гарантирует отсутствие угроз или
  предупреждений SmartScreen.
- Самоподписанный сертификат не получает автоматического доверия на компьютерах
  пользователей. Не устанавливайте неизвестные корневые сертификаты ради запуска.
- `onedir` и отключённый UPX уже используются в сборке; эти настройки не заменяют
  анализ антивирусного обнаружения.

## Известные ограничения

- `HKLM\...\Keyboard Layouts` не модифицируется (каталог системы).
- Для CJK IME (ja/zh/ko) KLID берётся из раскладки «по умолчанию» тега.
- После удаления часть приложений видит изменения только после выхода
  из системы / перезапуска проводника.
