# Keyboard Layout Cleaner

GUI-утилита для поиска и безопасного удаления «фантомных» раскладок
клавиатуры в Windows (Python 3.10+, CustomTkinter, только Windows).

## Возможности

- Сканер реестра: `HKCU\Keyboard Layout\Preload/Substitutes`,
  `HKCU\Control Panel\International\User Profile`,
  `HKCU\Software\Microsoft\CTF`, `HKEY_USERS\.DEFAULT\Keyboard Layout\Preload`,
  каталог имён `HKLM\...\Keyboard Layouts`, а также список языков через
  PowerShell (`Get-WinUserLanguageList`).
- Сопоставление BCP-47 ⇄ KLID HEX, динамические имена раскладок из HKLM.
- **Dry-run**: перед удалением показывается план — какие значения в каких
  ветках и какие раскладки/языки будут затронуты.
- Порядок «бэкап → удаление → синхронизация»: перед изменениями создаётся
  один `.reg` со всеми ветками (UTF-16 LE, BOM) **и** JSON-копия текущего
  списка языков.
- Рекурсивная очистка `User Profile` и `CTF` (включая подключи).
- Синхронизация списка языков выполняется «на месте»
  (`InputMethodTips.Remove`) — прочие настройки языка сохраняются;
  языки без раскладок удаляются целиком; список языков никогда не
  опустошается полностью.
- Журналирование в `layout_cleaner.log`.
- **Два интерфейса** (кнопка в шапке): «⌨ Терминал» — чёрный фон,
  моноширинный шрифт, плоские рамки, зелёные/циановые акценты; и
  «▦ Обычный» — классическая тема CustomTkinter. Выбор запоминается.
- **Яркость шрифтов** (меню в шапке): Тусклая / Обычная / Яркая /
  Максимальная — масштабирует все текстовые цвета без изменения фона;
  выбор тоже сохраняется (`%LOCALAPPDATA%\KeyboardLayoutCleaner\ui_prefs.json`).

## Установка и запуск

```bat
python -m pip install -r requirements.txt
python main.py
```

## Использование

1. «Сканировать систему» — поиск раскладок. Найденное сразу показывается
   списком в панели деталей; подсказка и пульсирующая подсветка указывают
   следующий шаг.
2. Выберите раскладку в списке — внизу появятся **все** сканируемые
   разделы со статусом «обнаружено / не обнаружено» и значениями записей.
3. «Удалить раскладку» — приложение покажет **план удаления** (dry-run)
   и спросит подтверждение.
4. После удаления данные автоматически пересканируются.
5. «↩ Восстановить из бэкапа» — откат любого удаления: выберите бэкап
   из списка (дата + состав), проверьте предпросмотр разделов и
   подтвердите. Будут применены `.reg` и, если есть снимок, список языков
   (`.langlist.json`). Если в бэкапе есть `HKU\.DEFAULT`, а прав нет —
   Windows запросит UAC прямо на импорт. Если раскладка не появилась
   сразу — выйдите из системы и войдите снова.

> Кнопка «🔑 Перезапустить как Администратор» видна только если прав нет:
> без админа системная ветка `HKU\.DEFAULT` пропускается — в деталях такая
> запись помечена «БЕЗ АДМИНА БУДЕТ ПРОПУЩЕНО», а Windows может вернуть
> раскладку после перезагрузки.

## Безопасность

- Все ветки экспортируются в `.reg` **до** удаления; список языков — в
  `.langlist.json`. Бэкапы лежат в `backups\` рядом с программой и
  применяются обратно кнопкой «↩ Восстановить из бэкапа».
- Запись в `HKEY_USERS\.DEFAULT` выполняется только с правами
  администратора; без прав ветка пропускается (баннер + кнопка
  «Перезапустить как Администратор», UAC).
- **Кеш TSF (CTF)**: фантомные профили удаляются целиком из
  `HKCU\Software\Microsoft\CTF\Assemblies` и `...\SortOrder\AssemblyItem`
  (включая десятичные HKL-значения вида `68748313` = `0x04190419`),
  а процессы ввода (`ctfmon.exe`, `TextInputHost.exe`) **останавливаются
  ДО** начала очистки и запускаются заново ПОСЛЕ всех операций с
  реестром и PowerShell — иначе служба держит кеш в памяти и переносит
  фантом обратно в реестр (гонка состояний). Если перезапуск не удался —
  достаточно перезагрузить ПК.
- **User Profile** очищается ТОЧЕЧНО: в профиле языка
  (`...\User Profile\en-GB`) удаляются только записи конкретной раскладки
  (`KeyboardLayoutPreload`, `InputMethodOverride`), **не** весь профиль
  языка и **не** активный язык из `Languages` — возможность вернуть
  раскладку через «Параметры → Язык и регион» сохраняется.
- Автотесты записи/удаления выполняются **только** в sandbox-ключе
  `HKCU\Software\KeyboardCleanerTest` (см. `test_sandbox.py`).
  Реальное удаление раскладок из живого профиля тестируйте в VM
  (Windows Sandbox / Hyper-V).

## Восстановление

1. Реестр: `reg import keyboard_layout_backup_<timestamp>.reg`.
2. Список языков (PowerShell):

```python
from cleaner import restore_language_list
restore_language_list("keyboard_layout_backup_<timestamp>.langlist.json")
```

## Сборка .exe (портативная версия)

```bat
build_exe.bat
```

или вручную:

```bat
python -m pip install pyinstaller
python -m PyInstaller keyboard_cleaner.spec --noconfirm --clean
```

Результат — папка `dist\KeyboardLayoutCleaner\` с `KeyboardLayoutCleaner.exe`.
Скопируйте **всю папку целиком** на флешку и запускайте
`KeyboardLayoutCleaner.exe` — Python на целевой машине не нужен.

## Портативный режим (флешка)

- Журнал (`layout_cleaner.log`) и бэкапы (`backups\`) создаются **рядом
  с exe** — приложение ничего не пишет во временные папки и не требует
  установки (спека: `keyboard_cleaner.spec`, тип сборки onedir — старт
  с USB быстрее, чем у onefile, т.к. нет распаковки при каждом запуске).
- Права администратора: UAC при старте не запрашивается (asInvoker);
  для очистки ветки `HKU\.DEFAULT` нажмите
  «🔑 Перезапустить как Администратор» внутри приложения.
- Первый запуск на другой машине может показать предупреждение
  SmartScreen — exe не подписан сертификатом («Подробнее → Выполнить
  в любом случае»).
- Пересборка после правок кода: `build_exe.bat`.

## Антивирус и ложные срабатывания

Утилита делает то, что эвристики антивирусов считают подозрительным: правит
ветки реестра пользователя, запускает PowerShell в скрытом окне, перезапускает
ctfmon, поднимает права через UAC. В сочетании с PyInstaller-упаковкой и
отсутствием цифровой подписи это регулярно даёт **ложные срабатывания**
(например, `Trojan:Win32/Cloxer` у Windows Defender — generic-детект
«скрытые дочерние процессы выполняют команды»), хотя вредоносного поведения
в коде нет и код открыт: [scanner.py](scanner.py), [cleaner.py](cleaner.py).

**Если Defender сработал на скачанный exe:**
1. «Безопасность Windows → Защита от вирусов и угроз → Журнал защиты» —
   восстановите файл из карантина; либо добавьте папку приложения
   в **Исключения**.
2. Помогите снять FP глобально — отправьте файл в Microsoft:
   <https://aka.ms/submitfalsepositive> (тип заявки «Software developer»,
   заявка о ложном срабатывании, приложите ссылку на этот репозиторий).
3. Подлинность файла сверяйте по **SHA256, опубликованному в описании
   релиза**, и/или соберите exe сами из исходников (см. «Сборка»).

**Разработчикам** (исключение только на вашу папку сборки, не отключайте
Defender целиком):

```powershell
Add-MpPreference -ExclusionPath "<путь к репо>\dist\KeyboardLayoutCleaner"
```

Дорожная карта по снижению FP: version-ресурс в exe (есть с v1.0.3);
подпись Authenticode (шаг в CI уже готов и активируется секретами
`WIN_CERT_*`; для Open Source доступна бесплатная подпись через
[SignPath.io](https://signpath.io/) — OSS-программа).

## Известные ограничения

- `HKLM\...\Keyboard Layouts` не модифицируется (каталог системы).
- Для CJK IME (ja/zh/ko) KLID берётся из раскладки «по умолчанию» тега.
- После удаления часть приложений видит изменения только после выхода
  из системы / перезапуска проводника.
