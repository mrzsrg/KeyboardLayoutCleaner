# FIX-12 — результат проверки гипотезы

**Дата:** 26.09.2026
**Статус: 🟡 ОТКРЫТА. Верификация НЕ проведена — заблокирована окружением.
Код НЕ изменён.**

> **Почему не закрыта как «не воспроизводится».** Пункт 2 плана требует
> результата прогона. «Не воспроизводится» без единого запуска — это утверждение
> о фактах, которых у нас нет: закрыть так значило бы заменить одну
> непроверённую гипотезу другой, более тихой. Пока данных нет, честное
> состояние задачи — «не проверено».

## Гипотеза

«Дыра в нумерации `Preload` (например `{1, 3}` после удаления значения `2`)
приводит к отбрасыванию раскладок, стоящих после неё».

## Итог одним абзацем

Проверить не удалось: требуется реальная смена пользователя на Windows,
а машина разработчика — **Windows 11 Домашняя**, где Windows Sandbox
недоступен (нужна Pro/Enterprise/Education). Косвенных данных, которые
доказывали бы или опровергали гипотезу, не нашлось ни в документации, ни
на живой системе. Согласно п.2 плана («если гипотеза не подтвердится —
закрыть задачу и не менять код») **пере-нумерация не реализована**.

## Почему верификация невозможна здесь

| Требование плана | Состояние |
|---|---|
| Windows 10 | ❌ нет |
| Windows 11 | ✅ есть, но Домашняя |
| Windows Sandbox | ❌ требует Pro/Enterprise/Education |
| Отдельная учётная запись | ❌ не создавалась (и требует цикла входа/выхода) |

`HypervisorPresent = True` — это наличие гипервизора (WSL2/Hyper-V), а не
доступность Sandbox: фича привязана к редакции, а не к железу.

Запускать проверку на единственной машине разработчика **нельзя**: скрипт
меняет список языков и `Preload`, и это тот же класс вреда, которым тестовый
прогон дважды сносил русскую раскладку. Поэтому скрипт требует явного ключа
`-IUnderstandThisIsATestMachine` и отказывается стартовать без него.

## Что удалось выяснить вместо этого

### 1. Документация

| Источник | Что говорит |
|---|---|
| [renenyffenegger.ch — Preload](https://renenyffenegger.ch/notes/Windows/registry/tree/HKEY_CURRENT_USER/Keyboard-Layout/Preload/index) | «The value whose name is 1 seems to be the default keyboard layout». Про **дыры — ни слова** |
| [xplantefeve.io — Export KeyboardLayout](https://xplantefeve.io/posts/Export-KeyboardLayout) | Реальный пример `Preload` в живом виде (`1,2,3,4` — без дыр), про дыры не упоминает |
| KB138354, SIL | Только соглашение о нумерации `1..n`. Утверждения о поведении при пропуске нет |

**Вывод:** гипотеза остаётся неподтверждённой и неопровергнутой. Утверждение
«дыра ломает раскладки» в документации Microsoft отсутствует — это остаётся
соображением внешнего ревью, а не фактом.

### 2. Живая система (только чтение)

```
HKCU\Keyboard Layout\Preload                  1=00000419, 2=00000409      дыр нет
HKCU\...\CTF\SortOrder\Language               00000000=00000419,
                                             00000001=00000409            дыр нет
```

Снимки `SAFETY_NET_*` — тоже без дыр; в сломанном состоянии
`SAFETY_NET_20260926_170000_AFTER_FIX28_BROKEN` значение `Preload` было
просто **удалено** (`1=00000409`), а не оставлено с пропуском. То есть
естественного эксперимента на этой машине не случилось.

### 3. Код — а вот это важно

Дыра не гипотетична: **текущий код её создаёт.**

```python
# mutate._clean_preload_keys удаляет значение ПО ИМЕНИ
Preload = {1: ru, 2: en, 3: de}
удаляем 2  ->  {1: ru, 3: de}   # дыра
```

Пере-нумерации в проекте нет (поиск по `renumber|уплотн` — пусто). То есть
FIX-12 — не «будущее улучшение», а описание реального поведения: после любого
удаления раскладки из середины списка остаётся дыра.

**Но это само по себе не аргумент за пере-нумерацию.** Значение `1`
определяет раскладку по умолчанию (подтверждено источником выше), поэтому
переписывание номеров — рискованная операция, оправданная только
доказанным вредом. Вред не доказан.

## Что сделано вместо реализации

Готов инструмент верификации — `verify/FIX12_verify_hole.ps1`:

```powershell
# Фаза 1 (на VM или одноразовой учётной записи)
.\verify\FIX12_verify_hole.ps1 -Mode Prepare -IUnderstandThisIsATestMachine
# выход из системы и вход
# Фаза 2
.\verify\FIX12_verify_hole.ps1 -Mode Check
# откат
.\verify\FIX12_verify_hole.ps1 -Mode Restore -IUnderstandThisIsATestMachine
```

Что он делает и почему именно так:

- **Удаляет СРЕДНЮЮ раскладку, а не последнюю.** Дыра в конце неинформативна;
  проверяется, теряются ли раскладки *после* пропуска — это и есть гипотеза.
- **Сверяется через `GetKeyboardLayoutList` (P/Invoke), а не по реестру.**
  Ценность реестра в том, что значение может остаться на месте, а раскладки
  в переключателе — исчезнуть. Именно это и наблюдалось у пользователя.
- **Смена пользователя обязательна** и делается вручную: кеш TSF/ctfmon
  пересобирается именно при входе. Скрипт прямо говорит об этом.
- **Откат восстанавливает** список языков, `Preload` и `CTF\SortOrder\Language`
  из полного бэкапа, снятого в фазе `Prepare`.
- **Пишет отчёт** `state/result_*.json` с ОС, версией, ожидаемым и
  фактическим составом — его и нужно приложить к задаче.

## Что нужно, чтобы закрыть задачу

Один прогон на Windows 11 Pro (или 10) с тремя раскладками. Интерпретация:

- **Все три раскладки на месте после входа** → гипотеза **не подтверждена** →
  задача закрывается по п.2 плана, код не трогаем.
- **Третья раскладка исчезла из переключателя** → гипотеза **подтверждена** →
  реализуется пере-нумерация по п.3–4 плана.

## Открытый риск, который это не снимает

Пока гипотеза не проверена, приложение может оставлять дыру в `Preload` после
удаления раскладки из середины списка. Считать это безвредным на основании
отсутствия документации — значит считать безвредным и на основании отсутствия
проверки. Если у вас есть возможность получить VM — это стоит сделать до
того, как задача превратится в «когда-нибудь».
